# FragmentsPicker（FragPicker）项目规划书

日期：2026-10-06。状态：首版需求已确认，正在按独立模块开发与真实服务验证。

## 已确认的实施基线

- 使用范围：个人自用；仍保留账号机制和数据所有权校验，便于未来扩展。
- 注册登录：用户名与密码。
- 视频平台：默认接入 parsevideo 支持的多平台，不人为限定为抖音或哔哩哔哩。支持列表与实际部署版本同步；平台声明支持不等于每个链接都保证解析成功。
- 模型：按最新要求，AI 对话使用 OpenAI 兼容格式的可配置供应商，首选 DeepSeek，不使用百炼聊天。聊天接口地址、密钥和模型名独立配置；每日总结与内容增强复用该文本模型适配器。embedding 使用 LangChain4j 提供的本地 ONNX 模型，优先中文模型，无需百炼 API Key；通过独立适配器管理模型版本。
- 媒体：视频和封面保存到私有 OSS，长期保留，删除记录时按清理策略删除对应对象。
- 日总结：北京时间每天 22:00 生成，次日补齐迟完成内容；不推送通知。
- 总结内容：摘要、要点、分类、关键词、原文时间戳。
- 检索：首版包含语义检索，需要覆盖“变化率”查找“导数”类表达。
- 使用量、视频时长、预算、Android 版本、服务器环境：用户无指定要求。候选默认 Android 最低 API 26；资源保护参数可配置，实际媒体约束按供应商限制和运行环境确定。
- 外部服务：用户表示已准备；parsevideo 地址已提供。阿里云凭据不写入本文件或源码，仅从环境变量加载。
- 外部配置进展：本机 MySQL 初始化方案已交付；听悟 AppKey 与 OSS Bucket 已提供，仅通过测试进程环境变量注入。OSS Endpoint 已确认为 oss-cn-shenzhen.aliyuncs.com。DeepSeek 聊天已读取本机配置并完成真实验证，embedding 无需外部凭据；真实凭据不写入项目文件。

## 1. 产品定位与目标

将用户主动保存的短视频转化为可回顾、可检索、可引用的个人知识记录。核心闭环为：分享投喂 → 异步解析与转写 → 结构化摘要入库 → 每日回顾 → AI 查找历史内容 → 卡片播放与原文核对。

首版面向个人自用，覆盖账号数据隔离、登录注册、多平台链接投喂、任务状态、视频详情与在线播放、日历历史、每日总结、语义检索、带来源卡片的 AI 对话、浅色与深色主题，以及圆点到胶囊到卡片的连续动画。公开运营、付费体系、社交分享、完整图像理解和离线视频下载列为后续能力。

## 3. 技术方案与目录

后端遵守 Java、Spring Boot、MyBatis-Plus、LangChain4j 和 MySQL 的技术选择，采用模块化单体服务。后台异步工作线程与 API 属于同一工程，但按职责分离；先通过 MySQL 持久化任务，使用任务租约和乐观锁协调工作线程，避免依赖进程内队列。后续达到实际吞吐瓶颈时再评估消息中间件。

Android 使用 Kotlin、Jetpack Compose、Material 3，采用 ViewModel + StateFlow 的单向状态流，数据访问通过 Repository。候选配套组件包括 Retrofit/OkHttp、Room、DataStore、Coil、Media3；最终版本在初始化模块时检查官方兼容性并锁定稳定版本。

Java 21 LTS 可作为候选基线，Spring Boot 与 LangChain4j 等版本以实际兼容性验证为准。MySQL 候选采用 8.4 LTS，数据库变更使用版本化迁移脚本。首版不预设必须增加 Redis 或独立向量数据库。

## 4. 视频投喂链路

1. Android 接收分享文本或粘贴输入，提取有效 URL；允许用户补充“为什么保存”的备注，是否展示该输入由用户确认。
2. API 鉴权、校验支持平台，保存投喂和持久化任务，立即返回记录 ID 与任务 ID。客户端提交幂等键，同一用户的同一资源按平台 ID 或规范化 URL 去重；跨用户记录保持隔离。
3. 后台调用 application.yml 中通过环境变量注入的 parsevideo 地址。适配器读取标题、作者、封面和视频直链；对空字段兜底，并通过服务端契约测试确认实际部署版的响应包装。
4. 流式下载视频及封面到私有 OSS 并长期保留，记录对象键、大小、类型和校验信息；限制下载大小、超时、重定向次数，并验证目标不是内网地址。下载地址和所有重定向目标均执行同样校验。
5. 使用听悟可访问、有效期足够的媒体 URL 创建离线任务，保存远端 TaskId。听悟接收的是 FileUrl，上传 OSS 是本项目为稳定访问与重播作出的设计选择，并非听悟接口要求直接上传二进制文件。
6. 首版以可恢复的定时轮询获取听悟结果；后续如使用回调，需要验证来源并保证幂等。超时区分任务仍处理中和明确失败，避免重复创建付费任务。
7. 下载听悟返回的转写、摘要等结果文件，提取带时间戳的文本片段、摘要和要点。结果内容持久化保存，不能只保存供应商临时结果 URL。
8. 调用可配置的文本模型完善分类、标签和检索片段，使用 LangChain4j 本地 embedding 模型生成语义检索向量。转写成功但增强失败时保留已得到的结果，允许重试增强步骤，并明确索引是否已就绪。
9. 投喂进入可浏览状态，并触发检索索引更新和当天总结的待重建标记。

业务阶段：QUEUED → PARSING → MEDIA_PREPARING → TRANSCRIBING → ENRICHING → READY；旁路状态包括 RETRY_WAIT、FAILED、CANCELLED。业务阶段与界面形态分别建模。

外部失败采用有限次数指数退避；记录阶段、错误码、次数、下次执行时间和人工重试入口。任务租约过期可恢复，服务器重启后从持久化状态继续。删除记录时阻止迟到任务结果重新写入已删除内容，并安排媒体清理。

进度默认展示处理阶段与不确定进度条；除非供应商提供真实进度，否则不编造百分比。

## 5. AI 对话与检索

LangChain4j 注册受约束的检索工具，例如 searchFragments、getFragmentDetail、getDailyDigest。用户可描述主题、作者、时间范围和学习目标，模型将查询意图转换为工具参数，服务端查询并返回来源记录。

- 工具的用户身份由认证上下文注入，模型不能指定或更改 userId；对话、历史和媒体接口同样检查所有权。
- 工具只暴露经过校验的过滤参数和查询服务，不提供任意 SQL 或任意 URL 执行能力。
- 普通检索使用标题、作者、标签和 MySQL 中文全文索引作为基础，验证中文分词与短词召回表现。
- 首版必须包含语义检索，使用 LangChain4j 提供的本地 embedding 模型生成片段向量，采用独立检索适配器；聊天供应商不需要具备 embedding 能力。本地模型通过 Maven 依赖随构建交付，启动不临时下载，记录模型版本和向量维度；以实际中文召回验证选型。个人自用规模先加载当前用户限定的候选向量进行精确相似度计算，配合关键词召回与重排；需用“变化率→导数”等实际样例验收。此方案不假设 MySQL 已具备原生向量搜索。
- 内容增删改时同步更新索引；摘要、标签与 embedding 保留版本，支持重建。
- 后续规模增长时单独评估向量数据库；首版业务数据和检索向量保存于 MySQL，不增加该部署依赖。
- 视频转写作为资料而非指令处理；回答需指向真实来源 ID。无结果或证据不足时明确说明，不虚构历史记录。
- 模型回复与卡片数据分离：模型生成文字与引用，服务器核验来源 ID 并生成封面、作者、摘要和播放入口。客户端不直接解析模型生成的 HTML 或任意媒体链接。
- 对话历史持久化，模型上下文按窗口和摘要控制 token 数；检索工具结果限制数量和长度。
- 对话通过 SSE 输出文字、来源卡片和结束事件；网络中断有明确重试行为，避免一条用户消息重复入库。

特别说明：“之前想学数学”可能是用户的保存意图，单凭视频转写不一定能判断。建议记录投喂备注、收藏或“想学”标签，以增强这类问题的可解释检索。

## 6. 每日回顾与历史

- 日历显示每日数量与处理状态；点选日期展示当日摘要、分类和分页记录。
- 当日归属按投喂时间与用户时区确定，UTC 保存原始时间；已确定的投喂归属日期保留，时区变更不静默改写历史。
- 每日总结包含主题分类、主要知识点、来源引用；学习建议为可选部分，并与来源事实区分。
- 采用北京时间，每天 22:00 更新当天总结，次日补齐迟完成内容；不推送通知。
- 定时任务为每位用户、每个业务日期生成记录，使用唯一键和内容版本控制避免重复生成。
- 晚到结果、删除、标签修订将摘要标为待更新；后台有界合并重建。展示生成时间、版本、成功条数和未完成条数。
- 无投喂日期显示空状态；全部失败时显示失败信息，不生成没有依据的知识总结。
- 支持按日期、分类、标签、作者和关键词组合查看。跨日期 AI 查找不受当前日历日期限制。

## 7. Android 页面与视觉

首版页面：登录、注册、今日投喂、历史日历、视频详情、AI 对话、个人设置。主要导航建议“今日 / 历史 / 对话”，设置通过个人入口进入。

- 使用 Google Material 3 的色彩角色、排版、图标和组件。默认跟随系统主题，支持手动浅色/深色切换；动态取色为可选设置。
- 首页突出投喂入口、正在处理的任务和今日摘要，避免无限推荐内容流。
- 视频卡片包含封面、标题、作者、摘要、标签和保存时间；详情页提供在线播放、转写原文和重点。
- Media3 播放器请求后端生成的当前可用 OSS 地址；媒体长期保留。出现删除或异常不可用时，明确显示状态并保留原平台入口。
- 接入系统分享菜单；链接先展示确认内容，防止批量误投喂。离线时可保存待提交输入并提示连接状态，实际后台恢复策略在该模块实现时确认。
- 网络错误、空状态、权限过期、任务失败和加载过程都有明确界面反馈。

动画组件独立验收：

| 阶段 | 形变与内容顺序 | 约束 |
| --- | --- | --- |
| Circle → Pill | 以中心为锚点向两侧展开，图标连续保留，文本与进度条依次出现 | 展开宽度受父容器约束，最终文字可读 |
| Pill → Card | 先增加高度，再补充宽度，保留图标和标题，再显示正文、时间和操作按钮 | 原元素复用身份，避免跳位和闪烁 |
| 失败 / 重试 / 完成 | 更新状态、色彩和操作入口 | 动画可中断，重试不造成卡片重复 |

动画使用 Compose 状态驱动的过渡与弹簧参数，时长在原型和真机上调试。遵守系统动画缩放，零动画设置时直接进入目标形态。验证大字体、TalkBack、低性能设备和长文本布局；视觉圆点的触摸区域仍应满足可访问尺寸。

## 8. 数据设计草案

| 表 | 主要职责 |
| --- | --- |
| users / refresh_tokens | 账号、密码哈希、时区、会话撤销与令牌刷新 |
| fragments | 用户投喂、原链接、平台资源 ID、作者、标题、备注、归属日期 |
| media_assets | OSS 对象键、媒体类型、大小、状态、保留期限 |
| ingestion_jobs / job_attempts | 阶段、租约、重试、远端 TaskId、错误与耗时 |
| transcripts / transcript_segments | 原文、语言、时间戳片段、处理版本 |
| fragment_summaries | 总结、要点、来源和生成版本 |
| categories / tags / fragment_tags | 分类与标签关系 |
| retrieval_chunks / embeddings | 检索片段、来源时间戳、embedding 模型与版本（首版必需） |
| daily_digests / daily_digest_sources | 日总结、业务日期、版本、参与投喂清单 |
| chat_sessions / chat_messages / message_sources | 用户对话、消息和经服务端校验的引用 |

用户数据以 user_id 与日期建立组合索引；同一用户投喂去重、日总结、幂等请求分别使用唯一约束。媒体二进制存对象存储，MySQL 保存对象元数据与结构化内容。保留供应商响应的必要审计信息并脱敏，不长期存储凭据或带签名的地址。

## 9. 接口边界草案

采用 /api/v1；统一分页、错误码与请求 ID。资源创建和异步任务返回语义明确的 HTTP 状态。

| 领域 | 主要接口 |
| --- | --- |
| 认证 | POST /auth/register、/auth/login、/auth/refresh、/auth/logout |
| 投喂 | POST /fragments、GET /fragments、GET /fragments/{id} |
| 任务 | GET /ingestion-jobs/{id}、POST /fragments/{id}/retry |
| 媒体 | GET /fragments/{id}/playback，生成当前有效播放地址 |
| 历史 | GET /calendar?month=、GET /daily-digests/{date} |
| 日总结 | POST /daily-digests/{date}/regenerate，限频且异步 |
| 对话 | POST /chat/sessions、POST /chat/sessions/{id}/messages，提供 SSE 响应 |
| 设置与删除 | GET/PATCH /users/me、DELETE /fragments/{id} |

## 10. 配置与运行

示例变量：DB_URL、DB_USERNAME、DB_PASSWORD、JWT_SIGNING_KEY、PARSEVIDEO_BASE_URL、ALIBABA_CLOUD_ACCESS_KEY_ID、ALIBABA_CLOUD_ACCESS_KEY_SECRET、TINGWU_APP_KEY、OSS_BUCKET、OSS_ENDPOINT、AI_BASE_URL、AI_API_KEY、AI_MODEL。

提交的示例配置仅包含占位符；真实 .env、local.properties、签名密钥、服务日志和构建产物排除出 Git。生产环境采用 HTTPS、私有 OSS、最小权限凭据；必要日志包含任务 ID 和错误类别，不记录令牌、密钥或完整用户原文。

部署候选：单台 Linux 服务器通过 Docker Compose 运行后端、MySQL 与 parsevideo，OSS、听悟和模型使用云服务。环境和现有资源待确认，不预先承诺特定部署平台。加入健康检查、迁移、MySQL 备份与恢复说明。

## 12. 关键风险与解决路径

- 视频地址可能因签名、防盗链、登录状态或平台风控失效：适配器区分失败原因，记录原链接，按选定保留策略准备稳定媒体地址。首版平台范围以真实样本验证结果为准。
- 纯音频转写无法保证理解无声字幕、图表和视觉演示：首版明确可处理的内容；需要 OCR、关键帧或图集理解时拆为独立模块。
- 异步云任务耗时不固定：先返回任务 ID，可重启恢复，分阶段显示状态；按已完成步骤重试，避免重复付费任务。
- 媒体存储、转写和模型调用都有成本：配置时长/大小、每日条数、并发与重试上限并记录用量。用户未指定预算或业务额度，不默认设置付费体系；实现时区分可选业务额度和必要的资源保护边界。
- AI 检索召回与摘要准确性需使用真实内容验证：建立少量人工可核对样例，测查找结果、引用和无结果行为，不承诺固定准确率。
